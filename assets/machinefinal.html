Parte 01

El sustrato · datos y el acto de aprender

Qué significa, exactamente, “aprender” de unos datos

Antes de cualquier modelo hay una bifurcación que decide todo lo demás: ¿alguien te dio la respuesta, o tienes que descubrir la estructura tú mismo?

Un dataset es una tabla: filas (observaciones) y columnas (atributos o features). Aprender es construir una función que opera sobre esa tabla. La pregunta es qué tipo de función, y eso depende de si existe una columna objetivo.

En el aprendizaje supervisado existe una variable respuesta y. El objetivo es estimar una función que la prediga a partir del resto, minimizando un error esperado sobre datos no vistos:

$$\hat f \;=\; \arg\min_{f}\ \mathbb{E}_{(x,y)}\big[\,L\big(y,\,f(x)\big)\,\big],\qquad f:\mathcal{X}\to\mathcal{Y}$$

En el aprendizaje no supervisado el objetivo cambia: caracterizar la propia distribución de los datos $p(x)$ —su densidad, sus ejes de variación, sus agrupamientos—. Se aprende la forma de los datos; el resultado es una descripción de su geometría.

01 · datos crudos

Solo puntos

Lo único que llega son coordenadas. Sin etiquetas, sin nombres. Pura geometría en un espacio de features.

02 · supervisado

Alguien trajo la etiqueta

Cada punto tiene una clase conocida. El problema se vuelve: aprender la frontera que separa los colores para predecir el color de un punto nuevo.

03 · no supervisado

La estructura emerge sola

Mismos puntos, sin etiqueta. El modelo no separa colores dados: descubre que hay grupos. La estructura no estaba anotada, estaba latente en la densidad.

sustrato.py
from sklearn.datasets import make_classification, make_blobs

# Supervisado: viene (X, y) — hay una respuesta que imitar
X, y = make_classification(n_samples=500, n_features=8)

# No supervisado: viene solo X — la estructura se infiere
X = make_blobs(n_samples=500, centers=3)[0]
precisión conceptualSupervisado estima un mapa condicional $p(y\mid x)$; no supervisado caracteriza la marginal $p(x)$. No son dos sabores del mismo problema: son dos preguntas distintas sobre el mismo objeto. Casi todo lo que sigue vive en la rama supervisada; volvemos a la no supervisada en la Parte 03.
Parte 02

El camino supervisado · el pipeline, paso a paso

El pipeline como una secuencia con orden no negociable

Ingesta → partición → baseline → modelo → optimización → evaluación → interpretación. El orden importa: saltarse un eslabón o invertir dos es la fuente más común de resultados que parecen brillantes y son mentira.

Tres herramientas cruzan todo el recorrido sin ser etapas en sí mismas: tqdm envuelve cualquier iterable y te da una barra de progreso (loops, trials, lectura por trozos); scikit-learn aporta el contrato común fit/predict_proba y la maquinaria de validación; Plotly es la capa de visualización interactiva. Las conoces; aquí son el andamiaje.

tqdm

Progreso sobre cualquier iterable. Un loop sin barra es un loop a ciegas.

scikit-learn

La API fit/predict, los splits, las métricas, los pipelines.

plotly

Gráficos interactivos; ideal para explorar distribuciones y SHAP.

01 · Ingesta — el formato ya es una decisión

Antes de modelar, eliges cómo entran los datos. No es trámite: el formato fija velocidad, tipado y techo de escala.

CSV es universal y legible; almacena texto plano, reinfiere los tipos en cada lectura y crece lento en volumen. Parquet y Feather son columnares y tipados: leen mucho más rápido y respetan los dtypes. JSON sirve para estructura anidada. Y hay un umbral en que conviene salir de pandas hacia polars o dask: cuando la tabla deja de caber cómoda en memoria.

ingesta.py
import pandas as pd
from tqdm import tqdm

# CSV: universal, sin tipos, lento en volumen
df = pd.read_csv("datos.csv")

# Parquet: columnar, tipado, lectura ~10x más rápida
df = pd.read_parquet("datos.parquet")

# Lectura por trozos con barra de progreso
trozos = pd.read_csv("grande.csv", chunksize=100_000)
df = pd.concat(t for t in tqdm(trozos, desc="ingiriendo"))

02 · Partición — separar para poder mentirte menos

El error que mides sobre los datos de entrenamiento refleja el ajuste a esos datos, que un modelo puede memorizar. Por eso reservas datos que el modelo ve recién al final. La cantidad que te interesa es el riesgo —el error esperado sobre datos nuevos—:

$$\underbrace{\mathbb{E}\big[L(y,f(x))\big]}_{\text{riesgo (lo que importa)}}\;\;\neq\;\;\underbrace{\tfrac{1}{n}\sum_{i=1}^{n} L\big(y_i,f(x_i)\big)}_{\text{error empírico (lo que ves)}}$$

La partición típica es train / validación / test. La estratificación conserva la proporción de clases en cada lado —crítico con clases desbalanceadas—.

particion.py
from sklearn.model_selection import train_test_split

X_tr, X_te, y_tr, y_te = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=0
)
# stratify=y conserva la proporción de clases en ambos lados
la trampa: fuga de datosEl escalador, la imputación y cualquier transformación se aprenden solo con train. Ajustar un StandardScaler sobre todo el dataset —incluyendo test— filtra información del futuro al pasado, infla la métrica y rompe la promesa de generalización. El test se transforma, nunca se aprende de él.
sin_fuga.py
from sklearn.preprocessing import StandardScaler

sc = StandardScaler().fit(X_tr)   # se APRENDE con train
X_tr = sc.transform(X_tr)
X_te = sc.transform(X_te)         # test SOLO se transforma

¿Qué hace cada scaler?

Cada transformación cambia la escala y el centro de los datos de una manera distinta. Elegir el scaler adecuado depende de la distribución de las features y de qué supuestos hace el modelo que sigue.

StandardScaler centra en cero y escala a varianza unitaria: $x' = \frac{x - \mu}{\sigma}$. Ideal cuando el modelo asume normalidad (regresión logística, SVM, PCA). MinMaxScaler comprime al intervalo $[0,1]$: $x' = \frac{x - x_{\min}}{x_{\max} - x_{\min}}$. Útil para redes neuronales y cuando se necesita preservar ceros (datos esparcidos). RobustScaler usa la mediana y el rango intercuartil: $x' = \frac{x - \text{mediana}}{\text{IQR}}$. Resiste outliers: la mediana y los cuartiles no se mueven por unos pocos valores extremos.

03 · Baseline — la hipótesis nula del desempeño

Un baseline es la vara contra la cual una métrica adquiere sentido. El DummyClassifier establece ese piso prediciendo sin aprender: siempre la clase mayoritaria, o al azar respetando proporciones.

baseline.py
from sklearn.dummy import DummyClassifier
from sklearn.metrics import f1_score

dummy = DummyClassifier(strategy="most_frequent").fit(X_tr, y_tr)
base = f1_score(y_te, dummy.predict(X_te), average="macro")
# 'base' es el piso: superarlo es la condición mínima de aprendizaje

04 · Modelos — la familia del gradient boosting

Hasta aquí el objetivo siempre es predecir una etiqueta de éxito: una columna del dataset que codifica lo que querés anticipar —si un cliente devuelve el crédito, si un lead convierte, si una transacción es fraudulenta—. Esa etiqueta es la $y$ que cada modelo intentará aproximar a partir de las features $X$. Sin etiqueta no hay aprendizaje supervisado: el modelo no tiene contra qué comparar sus predicciones.

XGBoost, LightGBM y CatBoost son tres ingenierías de una misma idea —árboles de decisión potenciados por gradiente—. Cada árbol nuevo se entrena para corregir el error residual del ensamble previo. Formalmente es descenso de gradiente en el espacio de funciones:

$$F_m(x) \;=\; F_{m-1}(x)\;+\;\nu\,h_m(x),\qquad h_m \approx -\,\nabla_{F}\,L\big(y,F_{m-1}(x)\big)$$

donde $h_m$ es el árbol que aproxima el gradiente negativo de la pérdida y $\nu$ es la tasa de aprendizaje. Lo que cambia entre las tres librerías es cómo construyen cada árbol y manejan los datos.

m = 0 · solo el promedio

El punto de partida

El ensamble empieza prediciendo una constante. El residuo —lo que falta por explicar— es toda la señal.

m = 1 · primer árbol

Un corte tosco

El primer árbol captura la tendencia gruesa. El residuo baja y queda estructura por modelar.

m = 5 · afinando

El ensamble se curva

Cada árbol corrige lo que el anterior dejó. La predicción se acerca a la forma real; el residuo se aplana.

m = 30 · casi ajustado

Suma de correcciones débiles

Muchos aprendices débiles, encadenados, componen un predictor fuerte. Demasiados sin regularizar: sobreajuste.

Cómo crecen los árboles: level-wise vs leaf-wise

El corazón de cada librería es cómo decide qué nodo expandir. Esta elección afecta la velocidad, la profundidad del árbol y la regularización implícita. XGBoost crece por nivel: todas las hojas de una misma profundidad se expanden juntas, manteniendo el árbol balanceado. LightGBM crece por hoja: elige la hoja que más reduce la pérdida, aunque el árbol quede desbalanceado y profundo. CatBoost usa árboles simétricos (oblivious): la misma condición de split en todas las hojas de un nivel, lo que produce árboles más rígidos pero más rápidos de evaluar.

XGBoost — el caballo de batalla

referenciaChen & Guestrin (2016). XGBoost: A Scalable Tree Boosting System. KDD.doi.org/10.1145/2939672.2939785

XGBoost (Chen & Guestrin, 2016) introdujo la función objetivo regularizada como innovación central. A diferencia del gradient boosting clásico, cada árbol $h_m$ se elige para minimizar no solo el error de predicción sino también la complejidad:

$$\mathcal{L}^{(m)} = \sum_{i=1}^{n} \ell\big(y_i, F_{m-1}(x_i) + h_m(x_i)\big) + \gamma T + \frac{1}{2}\lambda\sum_{j=1}^{T} w_j^2$$

Donde $T$ es el número de hojas, $w_j$ el peso de cada hoja, $\gamma$ penaliza cada hoja adicional y $\lambda$ es regularización L2 sobre los pesos. Esta regularización —junto con el crecimiento por nivel (level-wise)— produce árboles balanceados que rara vez sobreajustan sin necesidad de pruning posterior. El histogram binning agrupa features en cubetas para acelerar la búsqueda del mejor split, y el algoritmo es sparsity-aware: detecta automáticamente valores faltantes y les asigna la dirección que minimiza la pérdida.

Cuándo elegirlo: Competencias de ML tradicionales (tabulares), datos medianos (<10M filas), cuando la regularización y la estabilidad importan más que la velocidad cruda. Sus defaults son conservadores y robustos.

xgboost.py
from xgboost import XGBClassifier

# Parámetros distintivos de XGBoost
xgb = XGBClassifier(
    tree_method="hist",      # histogram binning (CPU rápido)
    grow_policy="depthwise", # crecimiento por nivel (default)
    gamma=0.1,               # ganancia mínima para partir una hoja
    reg_lambda=1.0,          # regularización L2 sobre pesos de hojas
    reg_alpha=0.0,           # regularización L1 (esparcidad)
    max_leaves=0,            # 0 = sin límite (usa max_depth)
    max_depth=6,             # profundidad máxima por árbol
    learning_rate=0.1,
    n_estimators=200,
)
xgb.fit(X_tr, y_tr)

LightGBM — velocidad sobre datasets masivos

LightGBM (Ke et al., 2017) se construyó sobre dos ideas que reducen drásticamente el costo de entrenamiento sin sacrificar precisión. GOSS (Gradient-based One-Side Sampling) retiene todas las instancias con gradiente grande —las que más informan el split— y submuestrea las de gradiente chico, concentrando el cómputo donde el error es mayor. EFB (Exclusive Feature Bundling) detecta features mutuamente excluyentes (raramente toman valores no-cero a la vez) y las empaqueta en una sola, reduciendo la dimensionalidad efectiva sin pérdida de información. El crecimiento por hoja (leaf-wise) elige siempre la hoja con máxima reducción de pérdida, lo que produce árboles más profundos y asimétricos pero con menos nodos totales para la misma precisión:

$$\text{hoja a partir} = \arg\max_{j}\;\frac{(\sum_{i\in I_j} g_i)^2}{\sum_{i\in I_j} h_i + \lambda}$$

donde $g_i$ y $h_i$ son el gradiente y la hessiana de la pérdida para la instancia $i$ en la hoja $j$. La contracara del leaf-wise es que puede sobreajustar con árboles excesivamente profundos; max_depth y num_leaves son hiperparámetros críticos.

Cuándo elegirlo: Datasets grandes (>10M filas), muchas features, cuando el tiempo de entrenamiento es la restricción principal. Gana casi todas las benchmarks de velocidad pura en tabulares.

lightgbm.py
from lightgbm import LGBMClassifier

# Parámetros distintivos de LightGBM
lgb = LGBMClassifier(
    boosting_type="gbdt",     # gradient boosting (también: dart, rf, goss)
    num_leaves=31,            # máximo de hojas (controla complejidad)
    max_depth=-1,             # -1 = sin límite (usar con num_leaves)
    learning_rate=0.1,
    n_estimators=200,
    min_child_samples=20,     # mínimo de datos por hoja
    subsample=0.8,            # fracción de datos por iteración
    colsample_bytree=0.8,     # fracción de features por árbol
    reg_alpha=0.0,            # L1
    reg_lambda=0.0,           # L2
    verbose=-1,
)
lgb.fit(X_tr, y_tr)

CatBoost — categóricas sin fuga

referenciaProkhorenkova et al. (2018). CatBoost: unbiased boosting with categorical features. NeurIPS.doi.org/10.48550/arXiv.1706.09516

CatBoost (Prokhorenkova et al., 2018) resuelve el problema más traicionero del boosting con variables categóricas: la fuga de target. Cuando codificás una categoría con el promedio del target, usás información del futuro si lo hacés sobre todo el dataset. CatBoost implementa ordered boosting: una permutación aleatoria de los datos donde cada fila solo ve estadísticas de las filas anteriores. Esto produce un encoding de categóricas libre de leakage sin necesidad de preprocesamiento manual.

Además, CatBoost usa árboles simétricos (oblivious trees): en cada nivel, todas las hojas aplican la misma condición de split. Esto los hace menos flexibles pero más rápidos de evaluar en inferencia —cada feature se consulta una sola vez por instancia— y más resistentes al sobreajuste. La combinación de ordered boosting + oblivious trees produce un modelo que con frecuencia iguala o supera a XGBoost y LightGBM con defaults, sin búsqueda de hiperparámetros.

Cuándo elegirlo: Datasets con muchas variables categóricas de alta cardinalidad (códigos postales, IDs de producto, ciudades). Cuando querés buena performance sin invertir tiempo en encoding ni tuning. Los defaults son notablemente buenos.

catboost.py
from catboost import CatBoostClassifier

# Parámetros distintivos de CatBoost
cb = CatBoostClassifier(
    iterations=200,           # número de árboles
    learning_rate=0.1,
    depth=6,                  # profundidad de árboles simétricos
    l2_leaf_reg=3.0,          # regularización L2
    border_count=254,         # bins para features numéricas
    cat_features=["pais","producto","canal"],  # ¡nativas!
    one_hot_max_size=3,       # one-hot solo para ≤3 valores únicos
    boosting_type="Ordered",  # Ordered boosting (default)
    random_seed=0,
    verbose=0,
)
cb.fit(X_tr, y_tr)

Resumen comparativo

Crecimiento: level-wise · árboles balanceados
Fuerte: regularización L1+L2, sparsity-aware, gamma para podar

LightGBM

Fuerte: GOSS + EFB para velocidad extrema

05 · Optimización — buscar hiperparámetros como quien optimiza una caja negra

referenciaAkiba et al. (2019). Optuna: A Next-generation Hyperparameter Optimization Framework. KDD.doi.org/10.1145/3292500.3330701

Los hiperparámetros (profundidad, tasa de aprendizaje, número de árboles) no se aprenden con fit: se buscan. Optuna trata esa búsqueda como optimización de una función objetivo opaca y cara de evaluar. En vez de probar todo (grid) o al azar (random), usa TPE —un muestreador que modela qué regiones del espacio prometen—.

Pruning — abortar lo que no promete

El pruning (poda) es la segunda gran idea de Optuna. En vez de esperar a que cada trial termine —gastando tiempo en combinaciones que desde las primeras épocas van perdiendo—, el pruner monitorea los valores intermedios que el trial reporta durante el entrenamiento y decide si vale la pena continuarlo o conviene abortarlo y probar otra cosa.

Esto es especialmente útil cuando el espacio de búsqueda es grande y muchas combinaciones son claramente malas. Sin pruning, un trial con learning rate 0.001 y max_depth 2 consume las 200 iteraciones antes de revelar su mediocridad. Con pruning, se corta en la época 10, liberando el presupuesto para explorar regiones más prometedoras.

Optuna ofrece varios pruners. MedianPruner compara el valor intermedio del trial contra la mediana de todos los trials en ese mismo paso: si está por debajo, lo poda. PercentilePruner usa un percentil (por defecto el 25) en vez de la mediana: más agresivo. HyperbandPruner combina pruning con asignación adaptativa de recursos (como número de épocas), inspirado en el algoritmo Hyperband para multi-armed bandits.

Para usar pruning, el trial debe reportar valores intermedios —típicamente la métrica de validación al final de cada época— con trial.report(valor, step=época). El pruner evalúa en cada reporte si el trial debe continuar.

optuna_pruning.py
import optuna
from optuna.pruners import MedianPruner
from optuna.samplers import TPESampler

def objetivo(trial):
    modelo = LGBMClassifier(
        n_estimators=trial.suggest_int("n_estimators", 200, 2000),
        learning_rate=trial.suggest_float("learning_rate", 1e-3, 0.3, log=True),
        max_depth=trial.suggest_int("max_depth", 3, 10),
    )
    # Reportar métrica intermedia cada 20 árboles
    for paso, n in enumerate(range(20, 2001, 20), start=1):
        modelo.set_params(n_estimators=n)
        modelo.fit(X_tr, y_tr)
        score = f1_score(y_val, modelo.predict(X_val))
        trial.report(score, step=paso)
        # El pruner decide si este trial sigue o muere aquí
        if trial.should_prune():
            raise optuna.TrialPruned()

    return score  # solo llega si sobrevive al pruning

estudio = optuna.create_study(
    direction="maximize",
    sampler=TPESampler(seed=0),
    pruner=MedianPruner(
        n_startup_trials=5,        # primeros 5 trials nunca se podan
        n_warmup_steps=3,          # primeros 3 reportes nunca se podan
        interval_steps=1,          # evaluar pruning cada 1 paso
    ),
)
estudio.optimize(objetivo, n_trials=100)
cuidado con el pruning agresivoSi el pruner es demasiado agresivo o la métrica tiene varianza alta en las primeras épocas, podés descartar trials que habrían remontado más tarde. Los parámetros n_startup_trials y n_warmup_steps existen para dejar que el pruner acumule evidencia antes de empezar a cortar.

06 · Evaluación — medir lo que importa, no lo que brilla

Un modelo puede clavar el 99% de acierto y ser inútil. Si solo el 1% de las transacciones son fraudulentas, predecir siempre «no es fraude» da 99% de accuracy... y cero fraudes detectados. La métrica correcta depende del costo relativo de cada error: en detección de fraude un falso negativo cuesta dinero; en diagnóstico médico, vidas. Elegir la métrica es elegir qué error te importa más.

Overfitting — cuando el modelo memoriza en vez de aprender

La señal más clara de overfitting es una brecha creciente entre train y validación: la métrica en train sigue mejorando mientras la de validación se estanca o empeora. El modelo ya no aprende patrones generalizables; empieza a memorizar ruido y peculiaridades de los datos de entrenamiento que no existen en datos nuevos.

El underfitting es el problema opuesto: ambas curvas son malas. El modelo ni siquiera capturó la estructura de los datos de entrenamiento. Ocurre cuando el modelo es demasiado simple, los hiperparámetros son muy restrictivos, o las features no contienen suficiente señal.

La regla práctica: medí siempre train y validación juntos. Una métrica sola —típicamente en test— te dice el resultado final, pero no te muestra si el modelo aprendió o simplemente se ajustó. La diferencia entre ambas curvas es el diagnóstico más barato y más informativo que existe.

El catálogo de métricas — cuál para qué problema

No hay una métrica universal. Cada una responde una pregunta distinta, y usar la equivocada produce modelos que optimizan lo que no te importa.

Accuracy

$\frac{TP+TN}{TP+TN+FP+FN}$
Fracción de aciertos totales. Solo útil con clases balanceadas. Con 95% de negativos, un modelo que siempre dice "no" tiene accuracy 0.95. No la uses si hay desbalance.

Precision

$\frac{TP}{TP+FP}$
De los que el modelo marcó como positivos, ¿cuántos lo son realmente? Alta precisión = pocas falsas alarmas. Importa cuando un falso positivo es caro (ej: mostrar una oferta irrelevante a un cliente premium).

Recall (Sensibilidad)

$\frac{TP}{TP+FN}$
De los positivos reales, ¿cuántos detectó el modelo? Alto recall = pocos positivos perdidos. Importa cuando un falso negativo es caro (ej: no detectar un fraude, no diagnosticar una enfermedad).

F1-score

$F_1 = \frac{2 \cdot P \cdot R}{P + R}$
Media armónica de precisión y recall. Penaliza el desbalance extremo entre ambas. Buena métrica global para clasificación con desbalance moderado. No distingue qué tipo de error preferís evitar.

AUC-ROC

$\text{AUC} = \Pr(s(x^+) > s(x^-))$
Probabilidad de rankear un positivo por encima de un negativo. Métrica de ranking, independiente del umbral. Con desbalance extremo, ROC puede verse optimista: los TN abundantes inflan la diagonal.

AUC-PR

Área bajo la curva precisión-recall. Mejor que AUC-ROC con desbalance extremo (<5% de positivos), porque ignora los TN y se concentra en cómo el modelo distingue la clase rara.

Log-loss

$-\frac{1}{N}\sum [y\log(\hat{p})+(1-y)\log(1-\hat{p})]$
Penaliza la confianza equivocada: predecir 0.99 cuando es negativo castiga mucho más que predecir 0.51. Útil cuando necesitás probabilidades calibradas, no solo clases.

MCC

$\text{MCC} = \frac{TP\cdot TN - FP\cdot FN}{\sqrt{(TP+FP)(TP+FN)(TN+FP)(TN+FN)}}$
Coeficiente de correlación de Matthews. La métrica más honesta con desbalance: solo es alta si el modelo acierta en todas las celdas de la matriz de confusión. Va de −1 a +1.

Regla práctica para elegir: si las clases están balanceadas (±30%), empezá por accuracy y F1. Si hay desbalance (<20% de positivos), usá AUC-PR y MCC. Si necesitás un umbral concreto para decidir, F1. Si lo que importa es rankear (ej: recomendar los N más probables), AUC-ROC. Si necesitás probabilidades calibradas (ej: pricing de riesgo), log-loss.

La distinción clave: F1 es un punto, AUC es una curva

La distinción es de naturaleza: cada una responde una pregunta distinta. F1 es la media armónica de precisión y recall, calculada en un umbral fijo: es una métrica de punto de operación. Mueves el umbral y cambia.

$$F_1=\frac{2\cdot\text{precisión}\cdot\text{recall}}{\text{precisión}+\text{recall}}$$

AUC-ROC es la probabilidad de que el modelo asigne mayor puntaje a un positivo que a un negativo tomados al azar: una métrica de ranking, independiente del umbral.

$$\text{AUC}=\Pr\big(s(x^{+})>s(x^{-})\big)$$

Mueve el umbral abajo y observa: el punto de operación recorre la curva ROC y el F1 cambia con él. El área (AUC) permanece constante, porque resume el ranking completo de scores con independencia del umbral.

¿Cuándo un F1 es "bueno"?

No existe un número mágico. Un F1 de 0.85 puede ser excelente en un problema difícil (predicción de abandono con señales débiles) y mediocre en uno fácil (clasificar dígitos manuscritos). El F1 solo tiene sentido comparado contra un baseline y contra el costo del error.

El baseline manda. Si tu DummyClassifier —que siempre predice la clase mayoritaria— obtiene F1 ≈ 0.42, entonces 0.60 ya es aprendizaje real. Si el baseline es 0.80 (clases muy separables), necesitás 0.90+ para justificar el modelo. La mejora sobre el baseline —no el número absoluto— es lo que mide el valor del modelo.

El dominio define el piso. En detección de fraude, recall 0.30 puede ser aceptable si cada fraude detectado ahorra millones y la precisión no desploma al equipo de revisión manual. En diagnóstico médico, recall 0.95 puede ser inaceptable si significa que 1 de cada 20 cánceres no se detecta. El negocio —no la estadística— fija el umbral de aceptabilidad.

La matriz de confusión no miente. Ante la duda, mirá los cuatro números crudos: TP, FP, FN, TN. Un F1 puede ser 0.80 con 80% precisión y 80% recall, o con 99% precisión y 67% recall. La misma métrica, dos modelos completamente distintos. Los números de la diagonal cuentan la historia que el escalar resume.

07 · Interpretabilidad — SHAP reparte el crédito de una predicción

referenciaLundberg & Lee (2017). A Unified Approach to Interpreting Model Predictions. NeurIPS.doi.org/10.48550/arXiv.1705.07874

Parte 03

El camino no supervisado · comprimir y agrupar

Cuando no hay etiqueta, quedan dos preguntas

Sin y que predecir, el trabajo es sobre la geometría de los datos: ¿puedo describir esto con menos dimensiones? y ¿hay grupos naturales aquí dentro?

01 · Reducción de dimensionalidad — PCA

referenciaJolliffe & Cadima (2016). Principal component analysis: a review and recent developments. Phil. Trans. R. Soc. A.doi.org/10.1098/rsta.2015.0202

En alta dimensión casi todo está lejos de todo: la maldición de la dimensionalidad degrada distancias y densidades. PCA responde con una proyección lineal que retiene la mayor varianza posible. Sus ejes son los autovectores de la matriz de covarianza, ordenados por autovalor; proyectar sobre los primeros conserva la estructura dominante.

$$\max_{\lVert w\rVert=1}\ w^{\top}\Sigma\,w\quad\Longrightarrow\quad \Sigma\,w=\lambda\,w$$

El problema de maximizar varianza bajo norma unitaria es un problema de autovalores. La varianza explicada de cada componente es su autovalor normalizado: te dice cuánta información retienes al descartar dimensiones.

pca.py
from sklearn.decomposition import PCA

pca = PCA(n_components=2).fit(X)
Z = pca.transform(X)                    # proyección lineal
print(pca.explained_variance_ratio_)    # varianza retenida por componente
cuando lo lineal no alcanzaPCA captura la estructura lineal. Para variedades curvas existen métodos no lineales como t-SNE y UMAP, que preservan la vecindad local. En sus mapas, la información confiable es la proximidad local: qué puntos quedan cerca de qué puntos. Las distancias globales y los tamaños de cluster responden a la parametrización, conviene leerlos con cuidado al clusterizar sobre el embedding.

UMAP — desplegar la vecindad antes de agrupar

referenciaMcInnes, Healy & Melville (2018). UMAP: Uniform Manifold Approximation and Projection.doi.org/10.48550/arXiv.1802.03426

Cuando los grupos viven en una variedad curva, una proyección lineal los encima. UMAP arma un grafo de vecinos en alta dimensión y busca una disposición en baja dimensión que conserve esa estructura local; el resultado suele abrir en islas lo que PCA dejaba superpuesto. Por eso aparece como paso previo a la clusterización: agrupar sobre el embedding de UMAP da fronteras más limpias.

Su objetivo aproxima la entropía cruzada entre el grafo de vecindades del espacio original y el del embedding —lleva a que puntos vecinos arriba queden vecinos abajo—:

$$\min_{\{y_i\}}\ \sum_{(i,j)}\Big[\,p_{ij}\log\frac{p_{ij}}{q_{ij}}+(1-p_{ij})\log\frac{1-p_{ij}}{1-q_{ij}}\Big]$$

02 · Clusterización — agrupar y, lo difícil, validar

Tres familias con supuestos distintos. k-means es particional: minimiza la inercia (suma de distancias al centroide), asume grupos esféricos de tamaño similar y exige fijar k. Jerárquico construye un dendrograma y no pide k de antemano. DBSCAN agrupa por densidad: detecta formas arbitrarias, marca el ruido y tampoco necesita k.

$$\min_{\{C_k\}}\ \sum_{k=1}^{K}\sum_{x\in C_k}\lVert x-\mu_k\rVert^{2}\qquad(\text{inercia de }k\text{-means})$$

Mueve k y corre las iteraciones: los centroides migran hasta estabilizarse. El problema de fondo aparece enseguida: la corrección del agrupamiento se evalúa con la sola geometría de los datos, sin una etiqueta de referencia.

Parte 04

El tiempo importa · cuando se rompe el supuesto iid

El orden temporal cambia las reglas del juego

Todo lo anterior asumía observaciones independientes e idénticamente distribuidas. En una serie temporal eso es falso: hay dependencia y hay orden. Dos consecuencias inmediatas reescriben el pipeline.

Primero, la partición ya no se baraja: el test es siempre el futuro, el train siempre el pasado. Mezclar es fuga temporal —usar el mañana para predecir el ayer—. Segundo, la validación cruzada se vuelve de ventana rodante o expansiva (TimeSeriesSplit): entrenas en una ventana, validas en el tramo siguiente, avanzas.

01 · la serie cruda

Señal en el tiempo

Un valor por instante. A simple vista, ruido con forma: sube, oscila, deriva.

02 · tendencia

Hacia dónde va

El componente de largo plazo. Lo que queda al borrar las oscilaciones: la dirección de fondo.

03 · estacionalidad

El pulso que se repite

El patrón cíclico —semanal, anual—. Prophet y X-13 viven de aislar y modelar exactamente esto.

04 · partición temporal

Entrenar en el pasado, probar en el futuro

El corte es una línea en el tiempo. Nunca se baraja: el modelo solo ve hacia atrás.

Tres herramientas, y una confusión que conviene deshacer

Prophet

De Facebook (hoy Meta), 2017. Modelo aditivo (GAM): tendencia + estacionalidad (Fourier) + feriados. Robusto a faltantes, buenos defaults, interpretable.

ARIMA

El forecaster estadístico clásico: AR + diferenciación + MA. Exige estacionariedad; se identifica por ACF/PACF.

X-13ARIMA-SEATS

Ajuste estacional. Estima y remueve la estacionalidad de series oficiales; usa SARIMA internamente.

Prophet descompone explícitamente la serie en un modelo aditivo:

$$y(t)=\underbrace{g(t)}_{\text{tendencia}}+\underbrace{s(t)}_{\text{estacionalidad}}+\underbrace{h(t)}_{\text{feriados}}+\varepsilon_t$$

ARIMA(p,d,q) modela la dependencia en términos autorregresivos y de media móvil sobre la serie diferenciada $d$ veces:

$$\Big(1-\textstyle\sum_{i=1}^{p}\phi_i L^{i}\Big)(1-L)^{d}\,x_t=\Big(1+\textstyle\sum_{j=1}^{q}\theta_j L^{j}\Big)\varepsilon_t$$

Prophet por dentro: cómo modela cada componente

referenciaTaylor & Letham (2018). Forecasting at Scale. The American Statistician.doi.org/10.1080/00031305.2017.1380080

Prophet —liberado por Facebook (hoy Meta) en 2017 como software de código abierto— es un Modelo Aditivo Generalizado (GAM) pensado para forecasting a escala. Su arquitectura responde a tres necesidades prácticas: (1) las series de negocio tienen estacionalidades múltiples —diaria, semanal, anual— que un ARIMA no modela con naturalidad, (2) los feriados y eventos especiales producen saltos que un modelo puramente autorregresivo no anticipa, y (3) la tendencia rara vez es lineal en el largo plazo.

La tendencia $g(t)$. Por defecto es lineal a trozos con changepoints automáticos: el modelo detecta dónde cambia la pendiente. También soporta crecimiento logístico con capacidad de saturación $C$: $g(t) = \frac{C}{1 + \exp(-k(t-m))}$. Los changepoints se ubican en los primeros $80\%$ de la serie y su magnitud sigue una distribución Laplace (regularización L1), lo que evita sobreajustar quiebres espurios.

La estacionalidad $s(t)$. Se modela con series de Fourier de orden $N$ (por defecto $N=10$ para la anual, $N=3$ para la semanal):

$$s(t)=\sum_{n=1}^{N}\Big(a_n\cos\frac{2\pi n t}{P}+b_n\sin\frac{2\pi n t}{P}\Big)$$

Donde $P$ es el período (365.25 para la anual, 7 para la semanal). Cada par seno/coseno captura una frecuencia distinta: los primeros pares modelan el ciclo grueso, los últimos afinan detalles de alta frecuencia. Usar series de Fourier en vez de dummies por día/mes reduce drásticamente la cantidad de parámetros y produce estacionalidades suaves.

Los feriados $h(t)$. Cada feriado $i$ se modela con un parámetro $\kappa_i$ que indica cuánto desplaza la predicción ese día. Se puede incluir una ventana alrededor del feriado para capturar efectos de víspera o ressaca.

La incertidumbre. Prophet propaga tres fuentes: ruido de observación $\varepsilon_t \sim \mathcal{N}(0,\sigma^2)$, incertidumbre en la tendencia (simulando changepoints futuros), y —opcionalmente— incertidumbre en la estacionalidad.

Parte 05

De predecir a intervenir · una introducción a la inferencia causal

El salto de “qué pasa junto con” a “qué pasaría si”

Todo el pipeline anterior optimiza una cosa: $P(Y\mid X)$, asociación. La inferencia causal apunta a otra cantidad: $P(Y\mid \mathrm{do}(X))$, intervención. El salto va de observar a actuar.

$$P\big(Y\mid \mathrm{do}(X{=}x)\big)\;\neq\;P\big(Y\mid X{=}x\big)\quad\text{en general}$$

El operador $\mathrm{do}(\cdot)$ fija $X$ por intervención y corta las flechas que entran a $X$, las que representan sus causas. Esto separa dos cantidades: el resultado de quien elige un tratamiento arrastra las causas de esa elección; el resultado de asignarlo aísla el efecto del tratamiento. La pregunta causal es contrafactual: ¿qué habría ocurrido con esta misma unidad bajo el otro escenario?

De la regresión lineal a la inferencia causal

referenciaPearl (2009). Causality: Models, Reasoning and Inference (2.ª ed.). Cambridge University Press.doi.org/10.1017/CBO9780511803161

La regresión lineal es el punto de partida natural para entender la inferencia causal porque ambas comparten una estructura de ajuste condicional. El salto está en qué se condiciona y por qué.

Etapa 1 — Regresión simple: $Y = \beta X + \varepsilon$. El coeficiente $\beta$ captura asociación, no causalidad. Si $X$ y $Y$ comparten una causa $Z$, la estimación de $\beta$ mezcla el efecto causal con el sesgo del camino trasero $X \leftarrow Z \rightarrow Y$. El estimador MCO es $\hat\beta = \frac{\mathrm{Cov}(X,Y)}{\mathrm{Var}(X)}$, que converge a $\beta + \gamma\cdot\delta$ donde $\gamma$ es el efecto de $Z$ sobre $X$ y $\delta$ el de $Z$ sobre $Y$.

Etapa 2 — Regresión múltiple: $Y = \beta X + \theta Z + \varepsilon$. Incluir $Z$ como control bloquea el camino trasero si $Z$ es un confusor observado. El estimador ahora es $\hat\beta = \frac{\mathrm{Cov}(X^\perp, Y)}{\mathrm{Var}(X^\perp)}$ donde $X^\perp$ es la variación de $X$ ortogonal a $Z$. Esto es el teorema de Frisch–Waugh–Lovell: condicionar equivale a aislar la parte de $X$ que $Z$ no explica.

Etapa 3 — Modelo causal: $P(Y \mid \mathrm{do}(X))$. La regresión múltiple funciona solo si (a) todos los confusores están en $Z$, (b) la forma funcional es correcta, y (c) no hay colisionadores. La inferencia causal moderna —grafos, do-cálculo, double ML— extiende la intuición del ajuste lineal a escenarios donde esas condiciones no se cumplen: confusores inobservables, no linealidad, alta dimensionalidad. La diferencia es que la regresión te da un coeficiente ajustado; el marco causal te da la cantidad identificada y los supuestos bajo los cuales es válida.

El confusor, y por qué el ajuste lo desactiva

Aquí está el corazón gráfico del problema. Una variable $Z$ que causa tanto el tratamiento $X$ como el resultado $Y$ abre un camino trasero $X\leftarrow Z\rightarrow Y$: induce correlación sin causalidad. Ajustar por $Z$ —bloquear ese camino— recupera el efecto causal.

La fórmula de ajuste por puerta trasera hace explícito el bloqueo: promedia el efecto condicional $P(y\mid x,z)$ sobre la distribución marginal del confusor $P(z)$, lo que cierra el camino trasero.

$$P\big(y\mid \mathrm{do}(x)\big)=\sum_{z}P\big(y\mid x,z\big)\,P(z)$$

Cuando agregar invierte el signo — la paradoja de Simpson

El caso ilustrativo más nítido del confusor. Toma un tratamiento $X$ y un resultado $Y$ medidos en tres grupos —tres niveles de severidad inicial $Z$—. Dentro de cada grupo, más tratamiento acompaña a un peor resultado. Al juntar los tres grupos, la asociación se vuelve positiva, porque el tratamiento se concentra en los grupos que ya partían mejor. El signo agregado y el signo dentro de cada grupo apuntan en direcciones opuestas; condicionar en $Z$ entrega el que tiene contenido causal.

Dos marcos para pensarlo

Resultados potenciales (Rubin). Cada unidad tiene dos resultados latentes, $Y(1)$ y $Y(0)$; su efecto individual es la diferencia. El problema fundamental: por unidad solo uno de los dos resultados llega a observarse. La cantidad estimable es el efecto promedio, bajo supuestos de ignorabilidad, solapamiento y SUTVA:

$$\tau=\mathbb{E}\big[Y(1)-Y(0)\big]$$

Grafos causales (Pearl). Un DAG codifica las relaciones; el criterio de puerta trasera dice qué ajustar y el do-cálculo formaliza la intervención. Su lección más contraintuitiva: ajustar un collider —una variable causada por otras dos— abre un camino espurio entre sus causas e introduce sesgo. La decisión de controlar una variable depende de su rol en el grafo.

collider · sesgo de selecciónEl ejemplo clásico: entre actores contratados, talento y atractivo aparecen correlacionados de forma negativa, aunque en la población general varíen de manera independiente. La contratación es el collider —depende de ambos—, y mirar solo a los contratados condiciona en él y fabrica esa correlación. El mismo mecanismo opera cada vez que la muestra se selecciona por una consecuencia del fenómeno que se estudia.

Los métodos, con fórmula, visualización y caso real

referencias claveRosenbaum & Rubin (1983) · propensity scores.doi.org/10.1093/biomet/70.1.41Card & Krueger (1994) · salario mínimo, DiD.doi.org/10.3386/w4509Angrist (1990) · lotería de Vietnam, IV.doi.org/10.2307/2006669Chernozhukov et al. (2018) · double ML.doi.org/10.1111/ectj.12097Wager & Athey (2018) · causal forests.doi.org/10.1080/01621459.2017.1319839

① Ajuste por propensity score

$$e(x)=P(T=1\mid X=x),\qquad \tau = \mathbb{E}\!\left[Y\frac{T-e(X)}{e(X)(1-e(X))}\right]$$

El propensity score $e(x)$ colapsa todas las covariables en una sola probabilidad de tratamiento. Ponderar por el inverso de esa probabilidad —o emparejar unidades con similar $e(x)$— crea una población sintética donde el tratamiento es independiente de los confusores. Lo esencial: comparar personas igualmente propensas a ser tratadas.

Caso real: LaLonde (1986) evaluó programas de capacitación laboral usando propensity scores contra un grupo control del CPS. El hallazgo fue que estimaciones no experimentales pueden diferir drásticamente de los resultados experimentales si el modelo de propensión no captura bien los confusores. Desde entonces es el benchmark estándar de evaluación de programas.

② Diferencias-en-diferencias

$$\tau = (\bar{Y}_{T,\text{post}}-\bar{Y}_{T,\text{pre}}) - (\bar{Y}_{C,\text{post}}-\bar{Y}_{C,\text{pre}})$$

El estimador resta la tendencia temporal del grupo de control a la del grupo tratado. La idea es que, sin la política, ambos grupos habrían evolucionado en paralelo. Lo que queda después de la doble resta es el efecto atribuible a la intervención.

Caso real: Card & Krueger (1994) usaron DiD para estimar el efecto del salario mínimo en Nueva Jersey comparando restaurantes de comida rápida en NJ y Pennsylvania antes y después del aumento. Encontraron que —contra la intuición— el empleo no cayó. El estudio redefinió el debate sobre salario mínimo con un diseño cuasi-experimental limpio.

③ Variables instrumentales

$$\beta_{\text{IV}} = \frac{\mathrm{Cov}(Z,Y)}{\mathrm{Cov}(Z,X)} = \frac{\text{efecto de }Z\text{ sobre }Y}{\text{efecto de }Z\text{ sobre }X}$$

Un instrumento $Z$ debe satisfacer tres condiciones: (1) relevancia —afecta al tratamiento $X$—, (2) exogeneidad —no tiene camino propio hacia $Y$—, y (3) exclusión —solo afecta $Y$ a través de $X$—. El estimador IV aísla la variación en $X$ que es atribuible a $Z$ (variación «limpia» del confusor) y la relaciona con $Y$.

Caso real: Angrist (1990) usó el sorteo de reclutamiento de Vietnam como instrumento para estimar el efecto del servicio militar sobre los ingresos futuros. El draft aleatorio afecta la probabilidad de servir pero no los ingresos futuros por otro canal. Encontró que los veteranos ganaban ~15% menos que los no veteranos una década después.

④ Double / Debiased Machine Learning

$$\theta_0 = \mathbb{E}\big[\psi(W;\theta_0,\eta_0)\big],\qquad \psi = (Y-\ell(X))(T-m(X))$$

Donde $\ell(X)=\mathbb{E}[Y|X]$ y $m(X)=\mathbb{E}[T|X]$ se estiman con ML flexible. El score $\psi$ es el producto de los residuos de dos modelos: el de resultado y el de tratamiento. Al ortogonalizar —quitarle a $Y$ y a $T$ lo que $X$ explica de cada uno— el efecto se estima sobre la variación no predicha, inmune al sesgo de regularización. La clave es usar validación cruzada (cross-fitting) para que los residuos se calculen sobre datos que los modelos no vieron.

Caso real: Chernozhukov et al. (2018) aplicaron Double ML para estimar el efecto del desempleo sobre la participación electoral en EEUU usando cientos de covariables del CPS. Sin la ortogonalización, los estimadores de ML regularizados producían sesgos de ~30%; con Double ML, el efecto estaba identificado y los intervalos de confianza eran válidos.

⑤ Puerta delantera (front-door)

$$P(y\mid \mathrm{do}(x)) = \sum_{m} P(m\mid x) \sum_{x'} P(y\mid m,x')P(x')$$

Cuando el confusor es inobservable —no se puede bloquear la puerta trasera—, un mediador $M$ que transmite todo el efecto causal abre una ruta alternativa. La fórmula estima el efecto en dos pasos: primero el efecto de $X$ sobre $M$ (no confundido, porque $M$ bloquea el camino trasero de $X$), luego el efecto de $M$ sobre $Y$ controlando por $X$.

Caso real: Pearl (2009) usa el ejemplo canónico: fumar ($X$) → alquitrán en pulmones ($M$) → cáncer ($Y$), con un factor genético no observado que confunde fumar y cáncer. Como el alquitrán media el efecto completo y no es afectado por el gen, la fórmula de front-door recupera el efecto causal del tabaco sin haber medido el confusor.

⑥ Causal forests · efectos heterogéneos

$$\tau(x) = \mathbb{E}\big[Y(1)-Y(0)\mid X=x\big]$$

Mientras los métodos anteriores estiman el efecto promedio, los bosques causales estiman el efecto condicional $\tau(x)$: cuánto rinde el tratamiento para cada perfil de covariates. Cada árbol del bosque parte los datos para maximizar la heterogeneidad del efecto entre hojas, usando una función de criterio adaptada (Athey & Imbens, 2016). El resultado es una función $\tau(x)$ que responde para quién funciona la intervención.

Caso real: Athey & Wager (2019) aplicaron causal forests a datos de un programa de subsidios en Indonesia, mostrando que el efecto variaba sustancialmente por nivel educativo y acceso a mercados. Los hogares más aislados y con menor educación —los que menos probabilidad tenían de recibir el subsidio— eran precisamente los que más se beneficiaban. Esta heterogeneidad habría quedado oculta estimando solo el ATE.

Cada método responde a una estructura de datos distinta. La elección depende de qué se observa, qué se puede suponer y qué variación está disponible.

para data scienceEste es el terreno de la metodología observacional: estimar efectos cuando el experimento queda fuera de alcance. El ML predictivo aporta los modelos flexibles que estos métodos usan por dentro; la teoría causal aporta la identificación, la pregunta de qué cantidad se estima y bajo qué supuestos.
